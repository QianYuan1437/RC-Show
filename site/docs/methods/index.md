# 方法总览

::: tip 一句话总结
本站实现的二十余种控制器按“需要什么”来分：需不需要动力学模型、需不需要末端力传感器、在关节空间还是任务空间、在线计算量多大。下表可以当作选型速查。
:::

## 统一接口

```python
from rczoo.robot import load_robot
from rczoo.dynamics import Dynamics
from rczoo.control import make

dyn = Dynamics(load_robot("panda"), "cuda")      # 批量标称模型（GPU）
ctrl = make("osc", dyn)                         # 按 ID 构造
tau = ctrl(state, ref)                          # state: t, q, qd, ft；ref: q/qd/qdd 和/或 p/R/v/a/f
```

- `State` 是测量（批量）：时间、关节位置 / 速度，以及末端六维力传感器读数 `ft`（环境作用在机器人上的力，世界坐标系）。
- `Ref` 可以同时包含关节参考 $(q,\dot q,\ddot q)$、TCP 参考 $(p, R, v, a)$、期望接触力 $f$ 与零空间姿态 $q_{\text{null}}$；每个控制器只读取它需要的字段。
- 有内部状态的控制器（积分、自适应参数、观测器）都**原地**更新状态张量，所以一个控制周期可以被捕获成 CUDA graph（<Src path="rczoo/control/base.py" symbol="Controller._keep" />）。

## 选型的几条经验

1. **只要求定点、负载已知**：PD + 重力补偿就够了，最简单也最稳。
2. **快速跟踪轨迹**：需要模型前馈（PD+ 或计算力矩）；如果负载会变，用积分、滑模或自适应。
3. **要与环境或人接触**：用阻抗（无力传感器）或导纳（有力传感器、本体刚性），恒力任务用混合力/位控制。
4. **有硬约束（力矩、限位）且约束会被触碰**：QP 或 MPC 比“算完再裁剪”好。
5. **难以建模、可以大量仿真**：强化学习，但精度通常不如基于模型的方法，部署前要做域随机化。
