# 控制演练场

浏览器里运行的完整控制回路：MuJoCo WASM 以 1 kHz 仿真机械臂，十几种控制器（与 Python 版逐项对照测试过的 TypeScript 移植）每 1 ms 计算一次力矩，PPO 策略通过 onnxruntime-web 推理。所有计算都在本地完成。

## 怎么玩

**轨迹跟踪**

- 拖动坐标轴（目标），参考由在线轨迹生成器平滑后交给控制器。下方左图是 TCP 到目标、到参考的误差。
- 拉高“未建模负载”：PD + 重力补偿、计算力矩、OSC 会下垂，速度模式和滑模几乎不受影响。
- 点“推一下”看抗扰；勾选“碰撞检测与反应”后再推，观测器会在几毫秒内把机械臂切换到“浮动”状态。
- 带上 1 kg 以上的未建模负载再打开碰撞检测，会看到误报：负载的重量被当成了外力。

**接触力控**

- 切换到这个场景后，探针下方 5 cm 出现一块平面，目标被投影到平面上。
- 拖动目标让探针沿平面滑动，下方右图是接触力与期望力。
- 对比笛卡尔阻抗（力不足）、导纳（软而稳）、混合力/位（精确）、并联力/位（无冲击）。

**手引导**

- 目标代表“人手”，通过一根 600 N/m 的弹簧拉 TCP。右图是手要用的力。
- 拖动示教（重力 + 摩擦补偿）最省力；把“关节干摩擦”调高、“摩擦补偿”调到 0，看看有多沉。
- 关节阻抗不是为示教设计的，手要用几十牛的力才能拉动。

## 与 Python 版的关系

| | Python（基准） | 浏览器 |
| --- | --- | --- |
| 物理 | MuJoCo Warp（GPU，256 世界） | MuJoCo WASM（单世界） |
| 标称模型 | 解析 RNEA（PyTorch） | 第二个 MuJoCo 实例（`mj_rne`、`mj_fullM`、`mj_jacSite`） |
| 控制器 | `rczoo/control/` | `lib/controllers.ts`（单元测试与 Python 力矩对照，相对误差 < 1e-4） |
| 参考 | 五次多项式 / 接触任务 | 在线轨迹生成（拖动目标） |
| 未移植 | — | 自适应、QP、MPC、iLQR（计算量或实现复杂度大，只在基准中运行） |

演练场的“世界”（负载、摩擦、接触面、推力、手）由 <Src path="site/docs/.vitepress/theme/lib/playground.ts" /> 驱动，它在 Node 中也有闭环测试：每个控制器都要能把 TCP 移动 10 cm 并稳住，力控制器要能压出 10 N，观测器要能检测到推力。
