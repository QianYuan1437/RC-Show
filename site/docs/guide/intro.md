# 项目介绍

::: tip 一句话总结
RC Zoo（Robot Control Zoo）把机械臂上常见的控制模式及其背后的控制律、以及更先进的控制方法放在**同一个仿真平台、同一套模型、同一组任务**上实现和比较。每个方法都有原理推导、代码链接、批量基准测试结果，大部分还能在浏览器里实时运行。
:::

## 为什么要做这个项目

打开一台协作机械臂的控制接口，看到的往往是几个“模式”：Franka 的 FCI 提供关节位置、关节速度、笛卡尔位姿、笛卡尔速度和**力矩**接口，并自带关节阻抗与笛卡尔阻抗两种内部控制器；珞石 xCore SDK 的实时模式同样有关节位置、笛卡尔位置、关节阻抗、笛卡尔阻抗和直接力矩控制。这些名称只说明“发什么指令”，并没有说明控制器内部是怎么把指令变成电机电流的：

- 位置模式下，机械臂为什么在快速运动时会“跟不上”，而加了一个工具后又会“下垂”？
- 阻抗模式和导纳模式都叫“柔顺控制”，它们的差别在哪里，各自适合什么场景？
- 力控为什么要先“摸到”表面再切换，为什么同一个控制器在软表面和硬表面上表现完全不同？
- MPC、iLQR、强化学习这些“先进方法”相对经典控制律到底改进了什么、代价是什么？

本项目对每个问题都给出**可运行的答案**：控制律的推导、与之一一对应的实现、在两台机械臂上数百个随机任务的统计结果，以及可以亲手改参数的交互演示。

## 两台机械臂

| | Franka Emika Panda | 珞石 xMate SR3-C |
| --- | --- | --- |
| 自由度 | 7（冗余） | 6 |
| 额定关节力矩 (N·m) | 87 × 4, 12 × 3 | 66, 66, 29, 16, 16, 16 |
| 末端 | 手爪（指尖之间为 TCP） | 60 mm 探针 |
| 力觉 | 探针球 + 六维力传感器（仿真） | 探针球 + 六维力传感器（仿真） |
| 模型来源 | mujoco_menagerie | 官方 URDF 的惯性参数 |

两者都是**关节力矩传感 + 力矩控制**的协作臂，所以本站所有控制器都以 1 kHz 的关节力矩为最终输出——这正是 Franka FCI 力矩接口和 xCore 实时力矩控制提供的能力。冗余的 Panda 在任务空间控制中还要处理零空间（肘部姿态），而 6 自由度的 SR3-C 没有零空间、更容易遇到腕部奇异，两台机械臂一起测试能暴露不少只在一种构型上才出现的问题。

## 统一的实验设置

- **仿真**：MuJoCo 4.0；基准测试用 [MuJoCo Warp](https://github.com/google-deepmind/mujoco_warp) 在一块 RTX 3090 上同时仿真 256 个世界，浏览器里用官方 MuJoCo WASM 绑定。物理步长与控制周期都是 1 ms。
- **标称模型与被控对象分离**：控制器只知道 MJCF 中的连杆参数（<Src path="rczoo/dynamics.py" symbol="Dynamics" />，用 PyTorch 在 GPU 上批量计算 $M$、$C$、$g$、$J$），被仿真的对象则可以带上未知负载、关节干摩擦或接触面（<Src path="rczoo/model.py" symbol="PlantConfig" />）。这样“模型不准”就是可以控制的实验变量。
- **力矩限幅**：所有控制器的输出都被裁剪到电机额定力矩，基准里记录饱和比例。
- **同一参考**：关节空间与任务空间控制器跟踪的是同一条运动（任务空间参考是关节参考的正运动学），因此可以直接比较 TCP 误差。

## 主要结论速览

以下数字来自 [基准测试](/benchmark/)（Panda，256 条随机五次多项式轨迹，1.5 s 内每个关节最多转 0.9 rad）：

- **模型前馈决定跟踪精度**。PD + 重力补偿的最大 TCP 误差约 6 mm，加上完整的惯性 / 科氏前馈（PD+ 或计算力矩）降到 0.6–0.7 mm，滑模控制不到 0.1 mm。
- **模型误差决定稳态精度**。加上 1.5 kg 未知负载后，所有不含积分或自适应项的基于模型的控制器都会稳态下垂（PD + 重力补偿约 12 mm，计算力矩 / OSC 约 9 mm）；滑模控制只剩约 1 mm，Slotine–Li 自适应在线辨识出负载后回到 0.07 mm，速度模式靠内环积分也能把稳态误差降到 0.2 mm 以下。
- **力控离不开力反馈**。笛卡尔阻抗只能靠“弹簧压缩量”产生力，表面越软、偏差越大；混合力/位控制在软、中、硬三种表面上的力误差都在 0.15 N 以内。
- **碰撞检测需要准确的负载模型**。动量观测器在标称负载下以 3–5 % 额定力矩的阈值在约 8 ms 内检测到全部碰撞且没有误报；一旦工具重量没有输入模型，负载重力就会被当成外力，几乎每条轨迹都会误报。
- **最优控制能省力**。在同样 1 s 内完成同样的运动，iLQR 规划的轨迹比五次多项式少用约 20 %（SR3-C 约 15 %）的 $\int\lVert\tau\rVert^2\,dt$。

## 代码结构

```
rczoo/
  robot.py, dynamics.py      机器人参数与批量刚体动力学（RNEA、M、C、g、J、回归矩阵）
  model.py, sim.py           被控对象（MjSpec 构建）与 MuJoCo Warp / CPU 仿真封装
  traj.py, qp.py             轨迹生成、TOPP-RA、在线轨迹生成；批量 ADMM QP 求解器
  control/                   控制器：joint.py, task.py, interaction.py, optimal.py, learned.py
  tasks.py, runner.py        基准任务与闭环运行器（每个控制周期捕获为一个 CUDA graph）
  bench/suite.py             基准测试
  rl/                        PPO 与 MuJoCo Warp 上的到达任务环境
  export/                    浏览器资源导出（网格、模型、ONNX、测试夹具）
site/                        本站（VitePress）；控制器的 TypeScript 移植在 docs/.vitepress/theme/lib/
```
